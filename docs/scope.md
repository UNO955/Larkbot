# 范围边界

## 产品定位

larkbot 的定位是开发团队在飞书里的“开发机替身”。它接收来自飞书群的自然语言问题，把任务投递到
开发机上的 traex 会话中执行，并让 Agent 读取开发机上的共享 public 知识库、日志和代码，最后把
过程入口和最终结论回传到飞书。

它关注的是“让开发机上的业务知识、日志排查和代码核验能力远程可用”，不是把飞书做成 IDE，
也不是把代码执行迁到云端。

## 当前做什么

当前范围：
- **远程入口**：单个飞书机器人，通过长连接接收 @、话题回复和引用回复。
- **权限边界**：Owner 负责配置和运维；控制台启用某个群聊后，群内成员可以直接提问或操作卡片。
- **会话映射**：飞书话题映射 larkbot Session，保留上下文边界。
- **本地执行**：用 node-pty 管理 traex 会话，保持本地仓库、凭证和 CLI 环境。
- **知识库增强**：读取开发机 public 知识库，先建立业务判定口径，再查日志和代码。
- **队列语义**：同一会话内 FIFO 排队，不打断当前 turn。
- **状态反馈**：分析卡片展示状态、token 和总耗时，最终回复卡独立展示。
- **过程观察**：控制台提供只读终端页面查看完整分析过程。
- **中断控制**：卡片 / 控制台停止当前 turn，但不关闭会话。
- **配置控制台**：编辑 bot、系统提示词 profiles、模型、落款、流式卡片开关，并按发起人和群聊管理会话。
- **模型发现**：通过 `traex models` 动态获取模型列表。
- **恢复能力**：daemon 重启后恢复会话路由，下一条消息 lazy resume。
- **生命周期清理**：每天凌晨 3 点关闭 3 天未活跃会话、删除 7 天未活跃路由，并私聊 Owner 汇总。
- **维护通知**：daemon 重启并连接飞书后，私聊 Owner 发送维护通知卡。
- **低噪声模式**：关闭流式卡片时用 `Get` / `DONE` 表情指示进度。

## 当前不做什么

| 不做 | 原因 |
|---|---|
| 复杂多租户权限体系 | 当前只需要 owner 配置 + 群聊授权，用户白名单只做补充 |
| 多 IM 平台落地 | 接口预留，但当前只接飞书 |
| 多 CLI 真正落地 | `CliAdapter` 预留，但当前只用 traex |
| 多 worker / 子进程隔离 | 单机单 CLI，daemon 内联 PTY 足够 |
| 细粒度文件 sandbox / 读隔离 | 当前依赖开发机受控环境和脱敏 public 知识库 |
| MCP 网关 | 当前需求不依赖 |
| 复杂任务 DAG / 多话题编排 | 超出 MVP |
| Webhook 公网入口 | 飞书长连接已满足，无需公网 |
| 成本账单 / 多租户统计 | 非核心 |
| 自动发布 / 自动回滚 | 工具只负责桥接，不碰发布链路 |

这些不做项不是能力缺失，而是为了让 MVP 集中解决“飞书远程驱动开发机替身完成项目排查”这条主链路。
每一项都可以后续扩展，但不应该污染当前的单开发机代理模型。

## 预留扩展口

- `ImAdapter`：后续可接企微 / Slack。
- `CliAdapter`：后续可接其他编程 CLI。
- `SessionStore`：后续可换 SQLite 或更完整的 resume 状态。
- 控制台 API：后续可接定时任务或外部触发。

## 命名边界

运行时名称统一为 `larkbot`：
- package name：`larkbot`
- bin：`larkbot`
- 控制台标题：`larkbot 控制台`
- 状态目录：`~/.larkbot`
