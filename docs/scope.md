# 范围边界：做什么 / 不做什么

明确边界是为了控制范围、不让实现失控——只做单机自用真正需要的部分，
其余能力先不做，但在架构上留好扩展口。

## v1 做（MVP）

- ✅ 单个飞书机器人（长连接接入）
- ✅ @ 机器人 → `reply_in_thread` 自动建话题
- ✅ 话题 = 一个 traex 会话（node-pty）
- ✅ idle/busy 状态机 + FIFO 队列（连发不打断）
- ✅ traex idle 检测（判定一轮结束）
- ✅ 实时流式卡片（增量 PATCH，文本 + 可选截图）
- ✅ 关闭流式卡片时用表情指示进度（`Get` / `DONE`）
- ✅ 会话关闭（卡片按钮 / 控制台）
- ✅ 主动命令注入（本地 HTTP）
- ✅ 建 / 管 bot 的本地 Web 控制台
- ✅ 单 owner 白名单（只响应本人）

## v1 明确不做

单机自用场景下用不到、或成本远超收益的能力，先不做：

| 砍掉的能力 | 为什么不需要 |
|---|---|
| 多 CLI 适配器体系 | 只用 traex；但保留 `CliAdapter` 接口留扩展口 |
| 多后端（tmux / zellij 等） | 只用 PTY |
| 每会话 fork worker 子进程 | 单机单 CLI，PTY 内联即可，省掉 IPC |
| 文件 sandbox / 读隔离 | 单人自用，信任本机环境 |
| MCP 网关 | 用不到 |
| 多话题编排 / DAG | 超出自用范围 |
| 会话接力 / 接管 | 用不到 |
| 跨应用 owner 身份边界 | 单 owner 白名单足够 |
| cost 统计 / 语音总结 | 非核心 |
| 多语言 / 国际版 host | 只用飞书国内版 |

## 预留扩展口（成本极低）

不实现，但架构上先埋接口，后续要扩展时不用重构：

- `ImAdapter` — 后续可接企微 / Slack
- `CliAdapter` — 后续可接 codex / claude
- `SessionStore` — 后续可换 SQLite / 支持 `--resume` 会话恢复

## v2+ 后续优化

- 会话持久化 + daemon 重启恢复（traex `--resume`）
- 截图渲染精细化 / 移动端快捷键
- 定时任务 / 外部 webhook 触发
- 多 bot / 多 CLI 真正落地
